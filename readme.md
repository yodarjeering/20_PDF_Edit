# PDF Studio

HTML / CSS / JavaScriptのみの、ローカルPDFページ編集アプリです。PDFのアップロード、外部CDN、ビルド工程はありません。PDF.js 5.6.205とpdf-lib 1.17.1を `vendor/` に同梱しています（ライセンスも同梱）。

## 起動

Node.js 20以降でリポジトリのディレクトリから実行します。

```sh
node server.mjs
```

ブラウザで http://127.0.0.1:8080 を開いてください。ES modules / Workerを使用するため、HTMLの直接起動（file://）には対応しません。サーバーは静的ファイル配信のみで、PDFデータはブラウザ内に保持します。新しいChrome / Edgeを推奨します。

## 操作

- 初期表示はダークモードです。右上のボタンでライト／ダークを切り替えられ、設定はこのブラウザに保存されます。PDF本文の色は変更しません。
- 編集結果タブはミント色、各PDFタブはブルー・パープルなど6色を順に割り当てます。選択中のタブは枠と下線でも区別できます。

- 「PDFを開く」で構成を置き換え、「PDF追加」またはファイルドロップで末尾へ追加します。複数ファイルを同時に選択できます。「PDFを開く」で複数PDFを選んだ場合は、各PDFタブだけを読み込み、編集結果は空で開始します。必要なページを各タブからコピーして編集結果へ貼り付けてください。単一PDFを開く場合はその全ページを編集結果へ配置します。「PDF追加」とドロップは全ページを末尾へ追加します。置き換え・追加もUndo可能です。
- 読み込んだファイル名をタブ・ビュー見出し・プレビューに表示します。「編集結果」タブでは結合後の構成を編集し、各ファイル名のタブではその元PDFだけを閲覧できます。各PDFタブの選択ページは切り替え後も保持されます。元PDFの閲覧タブでは削除・回転・履歴操作は無効です。「編集結果を保存」は編集結果全体を出力します。
- 出力から全ページを削除しても元PDFタブは残ります。「PDFを開く」による置き換えと、そのUndo / Redoに合わせてタブ構成も復元されます。長いファイル名はタブのツールチップとビュー見出しで確認でき、タブが多い場合は横スクロールできます。
- 左のサムネイルをクリックすると右側にプレビューを表示します。出力ページ番号と元ファイル・元ページ番号を区別して表示します。
- Ctrl / ⌘＋クリックで選択を切り替え、Shift＋クリックで範囲選択します。全選択はCtrl / ⌘＋Aです。
- 選択したページをドラッグし、移動先ページの上側の青い線へドロップすると、そのページの前に挿入します。複数ページは元の相対順序を保ちます。末尾専用のドロップ領域もあります。
- 長い一覧では端付近のドラッグでスクロールします。「ページへ移動」で遠いページへ移動できます。Alt＋上下矢印でも選択ページを移動できます。
- 削除（Delete）、左右90°回転は選択ページに一括適用します。回転ラベルは読み込み時からの追加回転を示します。元PDFの回転も描画・保存に反映します。
- UndoはCtrl / ⌘＋Z、RedoはCtrl / ⌘＋Shift＋ZまたはCtrl / ⌘＋Yです。最大100操作を保持します。
- Ctrl / ⌘＋Cで選択ページをコピー、Xで切り取り、Vで貼り付けます。複数ページの順序・回転を保持し、選択範囲の最後のページの直後（未選択なら末尾）へ挿入します。貼り付けごとに独立したページを作成します。切り取りと貼り付けはそれぞれUndo / Redoできます。
- 元PDFタブからもコピーできます。切り取り・貼り付けは「編集結果」タブで行ってください。ページのクリップボードはこのアプリ内のみで共有され、他のアプリ・ブラウザタブとは共有しません。入力欄での通常のコピー・貼り付けはそのまま使えます。
- 「PDF保存」で現在の並び順の `edited.pdf` をダウンロードします。全削除時は保存できません。元ファイルには上書きしません。

## ファイル構成と設計

### スクリーンショット・画像の編集

- OSのスクリーンショットなどの画像をコピーし、「編集結果」タブでCtrl / ⌘＋Vを押すと、プレビュー中のページへ配置します。「画像を追加」からPNG / JPEGファイルを選択することもできます（1画像30MBまで）。
- 編集結果が空の場合はA4の白紙ページを自動作成します。画像をクリックして選択し、ドラッグで移動、角の青いハンドルで縦横比を保った拡大・縮小ができます。
- 「画像を削除」または画像選択中のDeleteで画像のみを削除します。サムネイルをクリックすると画像選択が解除されます。追加・移動・サイズ変更・削除はUndo / Redoに対応します。
- 「表示倍率」は画面表示のみを変更します。「全体」または50～300%を選べます。画像の実際の出力サイズを変更する場合はハンドルを使用してください。拡大時はプレビューをスクロールできます。
- 画像はサムネイルにも反映され、保存PDFに埋め込まれます。ページのコピー時も画像を引き継ぎ、コピー先の画像編集は元ページに影響しません。元PDFの閲覧タブには追加画像を表示しません。
- 画像を選択してCtrl / ⌘＋Cでコピーし、Vで画像自体を複製できます。サイズを保持し、同じページには少しずらして配置します。他ページへは中央に配置します。Xで画像の切り取りもできます。画像を選択していない場合は従来のページコピーになります。画像・図形の内部コピーはこのアプリ内で使用します。
- 貼り付けはクリップボードの画像を優先し、画像がない場合はアプリ内でコピーした画像・図形またはページを貼り付けます。入力欄では通常の文字貼り付けを維持します。ページ外へ移動した部分は表示・印刷されません。切り抜き、OCRは未実装です。

### 図形の挿入

- プレビュー上部の「図形」で四角形・楕円・直線・矢印を選び、「＋ 挿入」で配置できます。編集結果が空なら白紙を作成します。
- 図形はピクトグラムボタンで選択します。線幅は0.25～32 ptの18候補から選べ、右の数値欄では0.1～100 ptを0.1 pt刻みで指定できます。選択した図形の線幅も変更できます。
- ドラッグで移動、角のハンドルで幅・高さを変更できます。画像のサイズ変更は従来どおり縦横比を維持します。
- 線色・塗り色・塗りなし・線幅を設定できます。選択中の図形にも即座に適用します。直線と矢印は線色を使用します。
- 画像・図形は「選択を90°回転」で中心を保って回転します。「選択オブジェクトを削除」またはDeleteで削除します。図形もCtrl / ⌘＋C・X・VとUndo / Redoに対応します。
- 図形の描画パスは `js/shapes.js` で共通化しています。プレビューはSVG、サムネイルはCanvas、PDF出力はpdf-libのベクターパスです。画像と図形はページの `images` 配列内で `type: 'shape'` を区別し、追加順に重ねて表示・出力します。
- `tests/images-browser.mjs` で画像の複製時にページ数・画像サイズが変わらないこと、図形のコピー・幅と高さの変更・回転、および4種の図形の保存PDFでの位置・色を検証しています。

### テキストボックス

- 文字欄に入力し「T テキストボックス」で挿入します。日本語・改行・幅に応じた折り返しに対応します。入力は最大10,000文字です。
- テキストを選択（またはダブルクリック）して上部の文字欄で編集し、「文字を適用」で確定します。文字サイズ6～144 pt、文字色、太字、左・中央・右揃えを設定できます。
- ドラッグで移動、角で幅・高さを変更できます。文字が収まるよう必要に応じて高さを自動的に広げます。文字そのものの大きさは文字サイズ欄で変更してください。
- 画像・図形と同様にCtrl / ⌘＋C・X・V、90°回転、削除、Undo / Redoに対応します。テキスト欄を編集している間のショートカットは通常の文字編集として扱います。
- `js/text.js` が文字の折り返しと描画を担当します。日本語システムフォントの見た目を保つため、追加したテキストボックスは透明背景の画像としてPDFへ保存します。出力後の追加テキストは検索・文字選択できません。元PDFの本文テキストは変更しません。フォントを埋め込んだ検索可能なテキスト出力は今後の課題です。
- ブラウザテストではピクトグラム操作、線幅3.7 pt、日本語テキストの追加・変更・コピー・Undo / Redo、PDF再描画での位置と色を確認しています。

画像はPDF座標の位置・幅・高さ・回転・画像データをページモデルに保持します。`js/images.js` が画像の読込・座標変換・編集用オーバーレイを担当し、プレビューとサムネイルで同じ変換を使用します。`js/exporter.js` はpdf-libの画像埋め込みで変更を反映します。既存PDF本文の画像化は行いません。

`node tests/images-browser.mjs` で、実クリップボードのPNG貼り付け、空ページ作成、元から回転したページへの配置、移動、サイズ変更、ズーム、Undo / Redo、画像削除を確認できます。保存PDFをPDF.jsで再描画し、画像の色をサンプリングして位置・サイズ・向きも検証します。Edgeで成功し、コンソールエラーはありませんでした。

| ファイル | 役割 |
| --- | --- |
| `index.html`, `style.css` | ツールバー、ページ一覧、大きなプレビュー |
| `js/documents.js` | 元PDFのバイト列、ファイル名、PDF.js Documentの管理、読み込み・テキスト抽出窓口 |
| `js/model.js` | 描画に依存しないページ構成、選択、履歴、操作 |
| `js/renderer.js` | PDF.jsのページ描画とviewportの計算 |
| `js/exporter.js` | pdf-libで元ページをコピーし、並び順と回転を反映 |
| `js/app.js` | UIイベント、選択表示、非同期処理、描画キュー |
| `server.mjs`, `package.json` | ローカル起動とテストコマンド |
| `tests/model.test.mjs` | ページモデルの自動テスト |
| `tests/browser.mjs` | Edgeでの操作・出力の統合テスト |
| `vendor/` | PDF.js本体、Worker、CMaps、標準フォント、WASM、pdf-lib、各ライセンス |

ページは `{ id, sourceId, sourcePage, rotation }` を持ち、配列位置を現在の並び順とします。元ページ番号は1始まりです。選択はページIDのSet、プレビュー対象はactive、範囲選択の起点はanchorで管理します。履歴にはページ構成・読み込んだ文書ID一覧・選択状態を保存し、元PDFのバイト列は重複コピーしません。元PDFタブは別の閲覧モデルを持つため、編集結果の並び替え・削除・回転に影響されません。現在・Undo・Redoのどこからも参照されなくなったPDFは解放します。

サムネイルはIntersectionObserverと直列キューで画面付近から描画し、画面外のキャンバスは解放します。一覧の要素自体は全ページ分生成します。PDF保存は画像へのラスタライズではなく、元ページのコピーです。

## 動作確認

```sh
node --test tests/model.test.mjs
node tests/browser.mjs
```

ブラウザテストは別プロセスでサーバーを起動した状態で実行します。テストだけがPlaywrightとpdf-libのNode用パッケージを必要とします。`PDF_TEST_RUNTIME` にこれらを含むnode_modulesの絶対パスを設定できます。未指定時は開発環境の同梱ランタイムを使います。Microsoft Edgeが必要です。アプリの使用にはこれらのテスト依存は不要です。

2026-09-26、Windows上の実Edge（headless）で確認済み:

- 1ファイル読み込み、3ページのサムネイル、ドラッグ並び替え
- Ctrl / Shiftによる複数選択、一括回転、一括削除
- 2ファイルから `A-3, B-2, A-1` の混在構成を作成
- 元から90°回転したB-2も含め、保存後の回転が `90, 180, 90` であることをpdf-libで検証
- 保存PDFをPDF.jsで再読込し、本文とページ順を検証
- 並び替え、回転、削除、追加の履歴、全削除後のUndo、Redo後の履歴分岐
- PDFファイルのドロップ、103ページの遅延サムネイル、末尾へのジャンプ
- 破損PDFのエラー表示と既存構成維持
- ブラウザの未処理例外・コンソールエラーなし

モデルテスト2件と上記ブラウザテストが成功。出力PDF・画面キャプチャ・テスト用PDFは `tests/output/` に生成し、Gitには含めません。

## 制約と今後の課題

- 暗号化・パスワード保護PDFは未対応です。複数ファイル読み込みの途中で失敗した場合は追加全体を取り消します。
- データと履歴はメモリ上のみです。再読み込み・タブ終了で失われます。
- PDF全体のバイト列はメモリに保持します。数百MB級や数千ページ級の性能保証はしていません。将来は一覧の仮想化や保存処理のWorker化を検討します。
- ページコピー後のフォーム、しおり、文書内リンク、署名などの文書全体に関わる機能の維持は保証しません。今回の検証対象はページ本文・順序・回転です。
- Firefox / Safari、タッチ操作、日本語フォントや特殊な注釈を含む多様な実PDFの回帰テストは今後の課題です。CMaps・標準フォント・WASMはローカル配信できます。

## 次フェーズ: 既存PDFテキスト編集

1. `DocumentStore.textContent(ref)` からPDF.jsの文字列、transform、幅、高さ、fontName、stylesを取得する解析モジュールを追加します。
2. `PdfRenderer.render()` が返すviewportを使ってPDF座標から画面座標への変換を統一し、独立したHTML overlayをプレビュー上へ配置します。回転・ズーム時も同じ変換を使います。
3. テキスト変更は元PDFを直接書き換えず、ページIDに紐づく編集コマンドとして保持します。ページ構成の履歴と統合できるようsnapshotを拡張します。
4. 出力は専用のテキスト変更適用モジュールを `exporter.js` に組み込みます。埋め込みサブセットフォント、文字コード、行分割、背景を評価し、対応可能なケースと代替フォントが必要なケースを明示します。

pdf-libには一般的な既存本文文字列をそのまま置換するAPIはありません。白い矩形と新しい文字の重ね書きは元文字を除去せず、複雑な背景も壊し得るため、本格編集や墨消しと同一視しません。元のコンテンツストリームを安全に変更する方式、または明示的な重ね書き方式を別途検討します。

参照: [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)、[pdf-lib PDFDocument](https://pdf-lib.js.org/docs/api/classes/pdfdocument)。
